HOW TO USE - QUICK START
================================================================================

Option 1: Hinge Only
  python quick_start_hinge.py

Option 2: Tinder Only
  python quick_start_tinder.py

Option 3: Both (Manual)
  from dating_agent.profile_aggregator import profile_aggregator
  
  agg = profile_aggregator()
  
  # Hinge
  h = agg.hinge_auth
  h_req = h.request_phone_verification("+1-555-111-1111")
  h_verify = h.verify_phone_otp(h_req['otp_id'], "123456")
  
  # Tinder
  t = agg.tinder_auth
  t_req = t.request_phone_verification("+1-555-222-2222")
  t_verify = t.verify_phone_otp(t_req['otp_id'], "123456")
  
  # Sync both
  result = agg.run_full_sync(
    hinge_user_id=h_verify['user_id'],
    tinder_user_id=t_verify['user_id'],
    limit=100
  )

Time per sync: 2-5 minutes (Hinge), 5-25 minutes (Tinder)

================================================================================
KNOWN LIMITATIONS & WARNINGS
================================================================================

Hinge:
  - Official SDK exists, but TOS likely prohibits automated scraping
  - Low risk of detection/ban
  - Conservative rate limits recommended
  - Suitable for personal use

Tinder:
  - No official API - reverse-engineered only
  - High risk of detection/ban
  - Aggressive rate limiting required (0.3-0.5 req/sec)
  - Explicit TOS violation
  - Potential CFAA issues if circumventing anti-bot
  - Use on throwaway accounts only
  - Stop immediately if errors increase
  - Wait 24+ hours between syncs

League:
  - Not yet integrated
  - Highest complexity
  - Requires browser automation (Playwright not in environment)
  - Explicit TOS prohibition
  - Highest legal risk

================================================================================
RECOMMENDATIONS
================================================================================

For Personal Use:
  1. Start with Hinge (safer, official SDK available)
  2. Once comfortable, add Tinder (if you accept risks)
  3. Avoid League (highest legal risk)

For Testing:
  1. Use throwaway/test accounts
  2. Don't fetch thousands of profiles
  3. Space out requests over time
  4. Monitor logs frequently

For Production:
  1. Implement proper encryption for tokens
  2. Use environment variables for secrets
  3. Add database backups
  4. Implement data retention policies
  5. Add GDPR/CCPA compliance
  6. Consider legal review
